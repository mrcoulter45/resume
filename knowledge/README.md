# Normalized career records

One UTF-8 JSON file per entity or independently useful contribution. Filename and
stable `id` must match. Read [the record schema](../schemas/record.schema.json),
[evidence rules](../docs/evidence.md) and [agent instructions](../AGENTS.md).

| Directory | Records at initial migration | Purpose |
| --- | ---: | --- |
| `experience/` | 7 | Employers, formal roles, dates, progression |
| `projects/` | 11 | Context, ownership, systems and initiatives |
| `accomplishments/` | 44 | Granular technical contributions, outcomes and awards |
| `skills/` | 18 | Languages/tools with demonstrated contexts or explicitly limited inventory evidence |
| `leadership/` | 3 | Functional ownership, engineering standards and execution policies |
| `education/` | 1 | Degree and focus areas |
| `additional/` | 3 | Academic work and other documented background |
| `profile/` | 1 | Application identity and city-level contact details |

Facts, not summaries, are citable. Notes and private facts retain context that may
never belong in a résumé. All originals remain separately registered; this first
normalization is not a claim that every career detail is known. Add depth over time
without replacing source evidence or rewriting this directory structure.
